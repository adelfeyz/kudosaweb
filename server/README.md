# Linux Server Setup for Docker-based Multi-Site Hosting

Complete guide for setting up an Ubuntu server to host multiple WordPress sites and Docker-based Next.js project instances.

## Overview

This setup allows you to:
- Host multiple WordPress sites, each with its own MySQL database (optional)
- Host multiple Next.js instances using Docker, each with its own SQLite database
- Manage all sites through Nginx reverse proxy
- Automatically generate SSL certificates with Let's Encrypt
- Manage containers with Docker Compose

## Prerequisites

- Fresh Ubuntu 20.04/22.04 LTS server
- Root or sudo access
- Domain names pointing to your server IP
- Minimum 2GB RAM (4GB recommended for better performance)

## Quick Start

### 1. Initial Server Setup

SSH into your server and run:

```bash
# Clone or upload the project files
cd /opt
git clone <your-repo-url> server-scripts
cd server-scripts

# Make scripts executable
chmod +x scripts/*.sh

# Run the main setup script
sudo ./scripts/server-setup.sh
```

This will install:
- Docker Engine
- Docker Compose
- Nginx
- MySQL (optional, for WordPress)
- PHP-FPM (optional, for WordPress)
- Certbot
- SQLite3

### 2. Create Your First Docker-based Next.js Instance

```bash
sudo ./scripts/create-docker-instance.sh client1 example.com 3000 3001
```

This script will:
- Create Docker instance directory structure
- Generate environment configuration
- Set up Docker Compose override
- Configure Nginx reverse proxy
- Generate SSL certificate
- Create management scripts (start, stop, restart, logs, remove)

### 3. Create Your First WordPress Site

```bash
sudo ./scripts/create-wordpress-instance.sh example.com mysite
```

This script will:
- Create a MySQL database
- Download and install WordPress
- Configure Nginx
- Generate SSL certificate

## Directory Structure

After setup, your server will have this structure:

```

├── instances/
│   ├── client1/
│   │   ├── .env
│   │   ├── docker-compose.override.yml

│   │   ├── restart.sh

│   │   └── remove.sh
```

## Configuration Files

### Database Configurations

- **MySQL**: `/etc/mysql/mysql.conf.d/99-low-memory.cnf`
- **PostgreSQL**: `/etc/postgresql/*/main/conf.d/99-low-memory.conf`

Both are optimized for 2GB RAM servers.

### Nginx Configurations

- WordPress template: `configs/nginx-wordpress.conf`
- Docker Next.js template: `configs/nginx-docker-nextjs.conf`
- Legacy Next.js template: `configs/nginx-nextjs.conf` (for PM2-based deployments)

## Docker-based Next.js Instance Setup

### Prerequisites

- Docker and Docker Compose installed (via `server-setup.sh`)
- Project files copied to server

### Creating an Instance

```bash
cd /opt/server-scripts
sudo ./scripts/create-docker-instance.sh <instance-name> <domain> [website-port] [api-port]
```

Example:
```bash
sudo ./scripts/create-docker-instance.sh client1 example.com 3000 3001
```

### Building Docker Images

Before starting instances, build the Docker images:

```bash
cd /path/to/pointerwebsite
docker compose -f docker/docker-compose.multi-instance.yml build
```

### Managing Instances

Each instance has management scripts in its directory:

```bash
cd /opt/docker-instances/instances/client1

# Start instance
./start.sh

# Stop instance
./stop.sh

# Restart instance
./restart.sh

# View logs
./logs.sh

# Remove instance (WARNING: deletes all data)
./remove.sh
```

## Docker Instance Configuration

### Environment Variables

Each instance has a `.env` file in its directory (`/opt/docker-instances/instances/<instance-name>/.env`):

```env
INSTANCE_NAME=client1
DOMAIN=example.com
WEBSITE_PORT=3000
API_PORT=3001
JWT_SECRET=<auto-generated>
BREVO_API_KEY=<optional>
OPENAI_API_KEY=<optional>
```

### Building and Starting

```bash
# Build images (from project root)
cd /path/to/pointerwebsite
docker compose -f docker/docker-compose.multi-instance.yml build

# Start instance
cd /opt/docker-instances/instances/client1
./start.sh
```

## Database Management

Docker instances use SQLite databases stored in Docker volumes. Each instance has its own isolated database.

### Backup Database

```bash
# Backup from running container
docker exec <instance-name>-api sqlite3 /app/data/database.db ".backup /app/data/backup.db"
docker cp <instance-name>-api:/app/data/backup.db ./backup-$(date +%Y%m%d).db
```

### Restore Database

```bash
# Copy backup to container
docker cp ./backup-20240101.db <instance-name>-api:/app/data/database.db
docker restart <instance-name>-api
```

## Managing Docker Instances

### List All Instances

```bash
ls -la /opt/docker-instances/instances/
```

### Start/Stop Instance

```bash
cd /opt/docker-instances/instances/<instance-name>
./start.sh    # Start
./stop.sh     # Stop
./restart.sh  # Restart
./logs.sh     # View logs
```

### View All Running Containers

```bash

docker ps --filter "name=-website"
docker ps --filter "name=-api"
```

### View Container Logs

```bash
docker logs <instance-name>-website -f
docker logs <instance-name>-api -f
```


## Troubleshooting

### Database Connection Issues

```bash
# Test PostgreSQL connection
sudo -u postgres psql -c "SELECT version();"

# Test MySQL connection
mysql -u root -p -e "SELECT VERSION();"
```

### Nginx Issues

```bash
# Test configuration
sudo nginx -t

# Reload configuration
sudo systemctl reload nginx

# View error logs
sudo tail -f /var/log/nginx/error.log
```

### Docker Issues

```bash
# View all containers
docker ps -a

# View logs
docker logs <container-name>

# Restart container
docker restart <container-name>

# Check container status
docker inspect <container-name>

# View resource usage
docker stats
```

### Memory Issues (2GB RAM)

If you experience memory issues:

1. Check current usage:
   ```bash
   free -h
   htop
   docker stats
   ```

2. Limit Docker container memory in `docker-compose.override.yml`:
   ```yaml
   services:
     website:
       deploy:
         resources:
           limits:
             memory: 512M
     api:
       deploy:
         resources:
           limits:
             memory: 256M
   ```

3. Adjust MySQL memory settings (if using WordPress):
   - `/etc/mysql/mysql.conf.d/99-low-memory.cnf`

4. Increase swap space if needed

## Security Best Practices

1. **Change default passwords**: Update MySQL and PostgreSQL root passwords
2. **Firewall**: Only open necessary ports (22, 80, 443)
3. **SSH**: Disable root login, use SSH keys
4. **Updates**: Regularly update system packages
5. **Backups**: Set up automated database backups

## Backup and Restore

### Database Backup

```bash
# Docker instance (SQLite)
docker exec <instance-name>-api sqlite3 /app/data/database.db ".backup /app/data/backup.db"
docker cp <instance-name>-api:/app/data/backup.db ./backup-$(date +%Y%m%d).db

# MySQL (WordPress)
mysqldump -u root -p database_name > backup.sql
```

### Restore

```bash
# Docker instance (SQLite)
docker cp ./backup-20240101.db <instance-name>-api:/app/data/database.db
docker restart <instance-name>-api

# MySQL (WordPress)
mysql -u root -p database_name < backup.sql
```

## Architecture

### Docker-based Deployment

- **Website Container**: Next.js standalone build
- **API Container**: Hono-based API server with SQLite
- **Database**: SQLite (one per instance, stored in Docker volume)
- **Reverse Proxy**: Nginx forwards requests to Docker containers

### Legacy PM2-based Deployment

The `api-server/` directory contains a legacy Express-based API server that can be used with PM2 if needed. However, Docker-based deployment is recommended for new instances.
